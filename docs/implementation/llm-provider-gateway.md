# بوابة مزوّدي نماذج اللغة في أثَر

## ما الذي يقدمه مستودع Free LLM API Resources؟
المستودع https://github.com/cheahjs/free-llm-api-resources هو دليل متغير لمزوّدي النماذج وواجهات API المجانية/التجريبية؛ ليس مكتبة تشغيل، ولا API موحدة، ولا يمنح أثَر مفاتيح مجانية تلقائيًا. صفحة `llm-providers.html` تعرض خيارات مع روابط الوثائق الرسمية، مع توضيح أن الحدود والتوفر تتغير.

## ما تم تنفيذه في الكود
- دالة `supabase/functions/generate-mcq/index.ts` تستخدم بوابة OpenAI-compatible قابلة للإعداد.
- أسماء الأسرار المدعومة: `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_PROVIDER`.
- للتوافق مع الإعداد السابق، ما زالت تقرأ `OPENAI_API_KEY` و`OPENAI_MODEL` كخيار احتياطي.
- يستدعي الكود `{LLM_BASE_URL}/chat/completions`؛ لذلك اختر فقط مزودًا يدعم هذه الصيغة، أو أضف adapter منفصلًا قبل ادعاء دعمه.
- المفاتيح لا توضع في الواجهة ولا في GitHub؛ يجب حفظها كأسرار Supabase Edge Functions.

## أمان الأسرار\nلا تضع أي مفتاح API في HTML أو ملفات JavaScript العامة أو GitHub. احفظ المفاتيح في Supabase Edge Function Secrets فقط.\n\n## الإعداد
- عند ضبط `LLM_API_KEY` وحده، تستخدم البوابة افتراضيًا OpenRouter مع النموذج `openai/gpt-oss-20b:free` المدرج ضمن نماذج OpenRouter المجانية في الدليل الذي تمت مراجعته. تظل الإتاحة والحصة قابلة للتغيير؛ إذا لم يكن النموذج متاحًا لحسابك، عيّن `LLM_BASE_URL` و`LLM_MODEL` إلى مزوّد/نموذج آخر متوافقين.\n- إذا وُجد `OPENAI_API_KEY` وحده، يستمر مسار التوافق القديم مع OpenAI و`gpt-4o-mini`.\n\n1. اختر مزوّدًا من الدليل، وأنشئ مفتاحًا وفق شروطه.
2. من Supabase Dashboard → Edge Functions → Secrets، أضف:
   - `LLM_API_KEY`: المفتاح الخاص.
   - `LLM_BASE_URL`: عنوان API الأساسي الموثق للمزوّد، من دون `/chat/completions`.
   - `LLM_MODEL`: معرف النموذج الدقيق الذي يتيحه حسابك.
   - `LLM_PROVIDER`: اسم وصفي اختياري يظهر في سجل الأخطاء.
3. لا تستخدم أي endpoint قبل التأكد من توافقه مع Chat Completions وJSON response format المستخدم في مولد MCQ.
4. جرّب طلبًا حقيقيًا بحساب مالك/مدير، ثم راجع إجابات الأسئلة يدويًا. بعض المزودين لا يدعمون `response_format: {type: "json_object"}`؛ عندها يلزم adapter يطبق JSON parsing/validation دون هذا الخيار.
5. لا يوجد مفتاح API مُدرج في المستودع، ولا يمكن اعتبار التوليد الحي مفعّلًا حتى يضيف صاحب المشروع الأسرار ويجتاز اختبار end-to-end.


- عند رفض مزوّد أو نموذج لخيار JSON mode بسبب خطأ 400/422، تعيد الدالة المحاولة مرة واحدة دون `response_format`، ثم تتحقق من JSON والحقول المطلوبة قبل إرجاع الأسئلة.

## حالة الاختبار
فحص الكود الساكن يثبت وجود الإعدادات القابلة للتغيير، لكنه لا يثبت أن مزودًا حيًا يعمل. يتطلب الاختبار الفعلي مفتاحًا صالحًا وحساب مالك فعليًا وإعدادات Supabase الصحيحة.
