## خطوات إكمال الإطلاق
1. افتح `auth.html` وسجّل الدخول بالبريد الذي تريد اعتماده للمالك. تأكد من وصول رابط الدخول واسمح بنطاق الموقع ضمن إعدادات Redirect URLs في Supabase.
2. بعد إنشاء الحساب، عيّن دور المالك من SQL Editor الموثوق، باستخدام بريدك الصحيح فقط:
   ```sql
   update public.profiles p
   set role = 'owner', updated_at = now()
   from auth.users u
   where p.id = u.id and lower(u.email) = lower('YOUR_OWNER_EMAIL');
   ```
3. افتح `admin.html` بعد تسجيل الدخول. اختبر رفع PDF وفيديو MP4/WebM وصورة، ثم جرّب النشر وإلغاء النشر والحذف.
4. أنشئ حساب طالب منفصلاً وتأكد من أنه لا يستطيع فتح لوحة الإدارة أو قراءة محتوى غير منشور.
5. أضف رابط الموقع النهائي إلى Supabase Auth Site URL وRedirect URLs.
6. اربط المستودع بخدمة استضافة مجانية مناسبة (Netlify أو Vercel) وتحقق من نجاح البناء وفتح جميع الصفحات دون 404. لم يتم إنشاء نشر جديد في هذه الخطوة.
7. حد الرفع الحالي 50 MiB؛ لا ترفع فيديوهات أكبر قبل إعداد رفع متدرج أو خدمة تخزين فيديو مناسبة.
8. راجع تنبيهات الأمان المتبقية في المشروع: الجدول السابق `public.users` بلا سياسات RLS، والدالة `public.rls_auto_enable()` تسمح بالتنفيذ للمستخدمين العامين/المسجلين. هذان العنصران موجودان مسبقاً ولم يتم تعديلهما لأنهما قد يخصان استخداماً آخر في المشروع.

## قبول الإطلاق
- تسجيل الدخول بالبريد يعمل فعلياً.
- صلاحيات المالك والمدير تفرضها RLS على الخادم، لا إخفاء الواجهة فقط.
- الطلاب لا يستطيعون إدارة المحتوى ولا قراءة المسودات.
- رفع الملفات وحذفها يعملان في التخزين الخاص.
- جميع صفحات الموقع تفتح من رابط نشر حقيقي، وتنجح اختبارات الجوال والحاسوب.
